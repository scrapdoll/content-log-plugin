# Content Log plugin — план реализации v1

## 0. Ребрендинг шаблона
- `manifest.json`: `id: "content-log-plugin"` (должен совпадать с именем папки), `name: "Content Log"`, версия `0.1.0`, `minAppVersion: "1.0.0"`, `isDesktopOnly: false` (все API кроссплатформенные), описание на русском.
- `versions.json`: `{ "0.1.0": "1.0.0" }`. `package.json`: имя `content-log-plugin`.
- Весь семпл-код (`MyPlugin`, `SampleModal`, dice-ribbon и т.д.) удаляется — правила ESLint `no-sample-code`/`sample-names` его не пропустят.
- Язык интерфейса — русский (команды, модалки, дашборд).

## 1. Модель данных — `src/types.ts`
- `ContentType = 'book' | 'movie' | 'game'`, `ContentStatus = 'planned' | 'in-progress' | 'finished' | 'abandoned'`.
- Схемы типов — данные, а не хардкод-логика (задел под кастомные типы в фазе 2): `CONTENT_TYPES: Record<ContentType, TypeSchema>`, где `TypeSchema = { id, label, icon, folder ('Books'/'Movies'/'Games'), fields: FieldDef[], progressKind: 'pages' | 'hours' | null }`.
- `ContentItem` — распарсенная карточка: файл, тип, title, статус, значения полей, started/finished.

## 2. Структура в vault и frontmatter-контракт
```
Content Log/            ← корень из настроек
  Books/
    Дюна/
      Дюна.md           ← карточка
      Notes/            ← заметки пользователя
```
- Ключи frontmatter: общие — `type, title, status, started, finished, rating`; книга — `author, pages-total, pages-read`; фильм — `director, year`; игра — `platform, hours-played`.
- Карточка опознаётся по валидному `type` во frontmatter + расположению под корнем. Файлы в `Notes/` и без `type` игнорируются индексом.
- Фильмы без прогресса — только статус и даты.

## 3. Настройки — `src/settings.ts`
- `ContentLogSettings { rootFolder: string }`, дефолт `'Content Log'`; таб с одним полем.

## 4. Индекс — `src/core/index.ts`
- `ContentIndex`: скан `vault.getMarkdownFiles()` под корнем, чтение frontmatter через `app.metadataCache.getFileCache()` (без ручного парсинга YAML), `Map<path, ContentItem>`.
- Инициализация в `workspace.onLayoutReady()` — лёгкий старт.
- `registerEvent` на `vault.create/modify/delete/rename` → debounce ~400 мс → точечное обновление → событие `onDidChange` → дашборд перерисовывается. Ручные правки и переименования файлов обрабатываются корректно.

## 5. Создание структуры — `src/core/templates.ts`, `src/core/scaffold.ts`
- Шаблоны карточек по типам с плейсхолдерами `{{title}}`, `{{author}}`, … (в теле — заголовок и секции «Впечатления»/«Цитаты»).
- `createContentItem()`: санитизация имени файла (`\ / : * ? " < > |`), разрешение коллизий (добавить год, затем `(2)`), `vault.createFolder` для папки единицы и `Notes`, `vault.create` карточки; при статусе «в работе» проставляется `started`.

## 6. Модалка добавления — `src/ui/add-content-modal.ts`
- Один модал: выбор типа (3 кнопки с иконками) → форма перестраивается по схеме типа (название*, автор/режиссёр/платформа, pages-total/год, статус, дефолт «в работе») → «Создать» → создание структуры, открытие карточки.

## 7. Дашборд — `src/ui/dashboard-view.ts` (живой view)
- `registerView` + `ItemView` (тип `content-log-dashboard`, иконка `library`), открытие вкладкой через `workspace.getLeaf('tab')`.
- Шапка: кнопка «+ Добавить», фильтры по типу и статусу, сортировка (по обновлению/названию/прогрессу).
- Строки: иконка типа, название + автор, статус-пилюля (planned — серый, in-progress — синий, finished — зелёный, abandoned — оранжевый), прогресс-бар `pages-read/pages-total` или часы для игр; клик — открыть карточку.
- Пустое состояние с подсказкой и кнопкой добавления. Перерисовка по событию индекса. DOM через `createEl`, стили — классы `.content-log-*` в `styles.css`.

## 8. Команды — `src/commands/`
- `add-content` — открыть модалку добавления.
- `open-dashboard` — открыть дашборд (+ иконка в ribbon).
- `update-progress` — на открытой карточке: модалка с числом и быстрыми кнопками (+10/+50 страниц, +1 ч); запись через `app.fileManager.processFrontMatter`; если статус был `planned` и введён прогресс — автоматически `in-progress` + `started`.
- `update-status` — выбор статуса; при `finished` проставляется дата, при `in-progress` заполняется `started`, если пусто.
- `add-note` — на открытой карточке: опциональный заголовок → `Notes/YYYY-MM-DD <заголовок>.md`, открыть.
- «Текущая карточка» = активный файл, найденный в индексе; команды неактивны вне карточек (`checkCallback`).

## 9. `src/main.ts` — только lifecycle
- Класс `ContentLogPlugin`: загрузка настроек, индекс в `onLayoutReady`, `registerView`, команды, ribbon, таб настроек.

## 10. Сборка и проверка
- `npm install` → `npm run build` (strict `tsc` + esbuild) → `npm run lint`.
- Папка плагина уже внутри vault: после сборки перезагрузить Obsidian (Ctrl+R), включить плагин в **Settings → Community plugins**.
- Смоук-тест вручную: создать книгу → проверить структуру папок; дашборд; обновить прогресс и статус; добавить заметку.

## Вне рамок v1 (фаза 2, отдельными модулями без переделки ядра)
- Интерактивная шапка карточки (`registerMarkdownPostProcessor`: пилюля статуса, прогресс-бар, кнопки прямо в заметке).
- Статистика на дашборде, кастомные типы контента, экспорт markdown-дашборда, оценки в UI.
